## 1. Isolated exercise

The T08 app is in `exercises/t08_concurrency.py`. It is not included in the
capstone application and is absent from its OpenAPI paths.

| Route | Execution |
| --- | --- |
| `GET /t08/async-sleep` | `async def`; awaits `asyncio.sleep()` on the event loop. |
| `GET /t08/sync-sleep` | `def`; FastAPI/Starlette dispatches it to an AnyIO worker thread. |
| `GET /t08/async-inline-blocking` | `async def`; calls a synchronous helper directly and blocks inline. |
| `GET /t08/slow` | Async wait used to generate overlapping slow requests. |
| `GET /t08/health` | Small health response used to check responsiveness. |

The response fields expose handler type, thread name/ID, and event-loop ID. The
IDs are diagnostic, not stable public API values.

## 2. Execution paths

FastAPI awaits async handlers and async dependencies on the event loop. An
ordinary sync handler or dependency is dispatched to a worker thread.

Calling an ordinary synchronous helper from an `async def` handler does not
change where that helper executes: Python calls it inline on the event-loop
thread. It must yield control through `await` or be offloaded explicitly.

AnyIO worker-thread capacity is shared and not unlimited. A sync route is not
automatically the wrong choice; blocking file, database, or other legacy work
can belong in the thread pool. CPU-heavy work is better isolated in processes
or a task system rather than occupying many event-loop or thread-pool workers.

## 3. Concurrent probe

Run the app separately:

~~~sh
uv run --locked uvicorn exercises.t08_concurrency:app --host 127.0.0.1 --port 8004 --reload
~~~

The direct benchmark requires no running server:

~~~sh
uv run --locked python exercises/t08_concurrency.py
~~~

It issues 20 slow requests and 20 health requests concurrently, using the
isolated ASGI app. It reports elapsed time, estimated throughput, status codes,
average latency, and p95 latency.

One local run produced:

| Metric | Slow route | Health route |
| --- | ---: | ---: |
| Status | 200 | 200 |
| Average | 108.10 ms | 0.71 ms |
| p95 | 114.41 ms | 1.16 ms |

The run completed 40 requests in 0.128926 seconds for an estimated 310.25
requests/second. This is an ASGI in-process baseline on the current machine,
not a production throughput claim. Re-run the probe before comparing changes;
machine load, scheduling, delay, and process configuration affect the result.

## 4. Context -> mechanism -> trade-off

**Async route.** Cooperative waiting allows overlapping I/O-bound requests.
The mechanism is `await`; the trade-off is that correct async I/O requires
async-native calls and CPU work can still block the loop.

**Sync route.** FastAPI sends an ordinary sync handler to an AnyIO worker
thread. The mechanism prevents blocking handlers from occupying the event loop;
the trade-off is shared thread-pool capacity and context-switch/dispatch cost.

**Concurrent experiment.** The slow and health routes overlap, so the fast
health route demonstrates that cooperative waiting is not blocking the health
work in the same process. The trade-off is that this ASGITransport timing is
not a network/load-generator measurement.

**CPU and process parallelism.** Cooperative concurrency overlaps waiting;
it does not make CPU-heavy Python work run simultaneously on all cores. CPU
parallelism requires a suitable process or separate worker pool, and it has
coordination, serialization, and deployment trade-offs.
