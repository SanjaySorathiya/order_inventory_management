## 2. Header and cookie binding

GET /headers-cookies accepts these optional inputs:

| Python declaration | HTTP input | Omitted value |
| --- | --- | --- |
| x_request_id with Header() | X-Request-ID header, any capitalization | null |
| x_demo_tag with Header(convert_underscores=False) | Literal x_demo_tag header | null |
| theme with Cookie() | Cookie: theme=dark | null |

Header() converts parameter underscores to hyphens by default. Header names
are case-insensitive; setting convert_underscores=False retains the underscore.
Some intermediaries reject underscore headers, so that option here is a
comparison exercise. See [FastAPI header parameters](https://fastapi.tiangolo.com/tutorial/header-params/).

Cookie() reads the cookie, not a query parameter with the same name.
The theme cookie demonstrates input binding, not authentication. Header values
are limited to 1-64 characters and theme to 1-20 characters when supplied.
See [FastAPI cookie parameters](https://fastapi.tiangolo.com/tutorial/cookie-params/).

## 3. JSON, forms, and multipart

| Route | Expected body | Example |
| --- | --- | --- |
| POST /json | application/json | {"message":"hello"} |
| POST /form | application/x-www-form-urlencoded | message=hello |
| POST /upload | multipart/form-data with a boundary | One file part and one label text part |

The message field is required and 1-120 characters. The JSON model rejects
extra fields. The form route also accepts a text field in multipart encoding.
Supplying JSON to the form route, form encoding to the JSON route, or a text
field in place of UploadFile produces 422 in these exercises.

A request has one body encoding. File and text parts can share a multipart
body; a JSON document is not simultaneously the top-level body of that
request. A JSON string could be another explicitly parsed multipart field in
a different contract. See
[FastAPI forms with files](https://fastapi.tiangolo.com/tutorial/request-forms-and-files/).
Let the HTTP client generate multipart boundaries; do not manually set a bare
multipart Content-Type header.

The input exercises return 200 because they inspect/echo input rather than
create persistent resources. The label is required and 1-80 characters.

## 4. Controlled UploadFile exercise

The agreed policy is one nonempty .txt file with declared media type
text/plain, at most 2 MiB (2,097,152 bytes). Extension matching is
case-insensitive; media-type parameters are ignored. Content must decode as
UTF-8 and must not contain ASCII control characters other than tab, carriage
return, and newline.

The route returns the filename, content_type, size_bytes, character_count, and
label. It never saves an upload under a client-supplied name, returns the file
contents, or retains an upload.

| Condition | Status | detail.code |
| --- | --- | --- |
| Exactly the maximum byte count, valid text/type | 200 | Successful summary |
| More than 2,097,152 file bytes | 413 | file_too_large |
| Wrong filename extension or declared media type | 415 | unsupported_file_type |
| Empty file | 422 | empty_file |
| Invalid/incomplete UTF-8 or forbidden controls | 422 | invalid_text |
| Repeated file/label or unexpected multipart fields | 422 | invalid_upload_fields |
| Missing file/label, invalid label, or text instead of a file | 422 | Structured validation entries |

Filename and MIME metadata alone do not establish a file's content. The text
decoder provides the content check for this exercise; it is not malware
scanning. Invalid text can fail before a later chunk would exceed the size
limit.

The handler reads in 64 KiB chunks and counts bytes without loading the
whole file into a bytes object. An incremental decoder preserves characters
split across chunks and rejects an incomplete final character. Character count
is the count of Unicode code points, separate from the byte limit.

UploadFile wraps a SpooledTemporaryFile: smaller data
stays in memory, and larger data rolls over to a temporary disk file.
See [FastAPI UploadFile](https://fastapi.tiangolo.com/tutorial/request-files/).
In installed Starlette 1.10.0, MultiPartParser.spool_max_size is 1 MiB;
the accepted 2 MiB test therefore exercises real disk rollover.
That threshold is a framework implementation detail, separate from our 2 MiB
file policy. Python also supports explicit rollover; calling fileno() can force
it, so the observation tests do not call fileno(). See
[Python spooled temporary files](https://docs.python.org/3.13/library/tempfile.html#tempfile.SpooledTemporaryFile).

The inspection helper closes UploadFile in finally on
success, expected rejection, or a read failure. The route closes the parsed
form in finally, including extra files rejected before inspection. FastAPI's
request cleanup also closes parsed forms when body validation rejects input
before the handler runs. The tests assert actual temporary-file closure before
their own fixture cleanup.

FastAPI parses multipart data before
calling the handler. The 2 MiB check therefore limits accepted file processing;
it is not a limit on bytes received or initially spooled. Starlette's
max_part_size bounds non-file fields, not uploaded file bytes. A deployment
would need a separate total request-body limit before parsing. See
[Starlette request files and parser limits](https://starlette.dev/requests/#request-files).
This exercise adds no global ingress middleware.

## 5. Initial HTTP response contract

The [T01 contract](T01_D1.md#transport-validation-and-errors) remains the
baseline. Main inventory routes already implement the following behavior;
T04 adds focused checks of the complete response contract.

| Outcome | Status | Required response behavior |
| --- | --- | --- |
| Read/update existing inventory | 200 | JSON representation |
| Create inventory | 201 | Created JSON and Location resolving to its detail route |
| Deactivate inventory | 204 | Zero body bytes; no JSON null or Content-Type |
| Absent or hidden inactive item | 404 | detail.code = inventory_item_not_found |
| Duplicate normalized SKU, including a deactivated SKU | 409 | detail.code = duplicate_sku |
| Invalid request fields | 422 | detail list with loc, msg, and type |
| Unsupported HTTP method | 405 | Allow header includes the supported method |
| Exercise-only GET /errors/rate-limited | 429 | Structured detail and Retry-After: 60 |

Expected failures raise HTTPException. For example, /errors/rate-limited always
raises 429 with this body and the Retry-After header:

~~~json
{"detail":{"code":"rate_limited","message":"Try again later."}}
~~~

That endpoint demonstrates optional exception headers; it does not implement
rate limiting. See [FastAPI HTTPException and custom headers](https://fastapi.tiangolo.com/tutorial/handling-errors/).
Domain errors use detail.code/detail.message. Request validation uses the
existing safe renderer, which omits submitted values and validator context.
A generic error envelope and operational middleware remain T17.
Authentication headers and enforcement remain T15-T16.

## 6. Run the examples

With the exercise running on port 8002, use Windows PowerShell:

~~~powershell
$exerciseBase = "http://127.0.0.1:8002"

curl.exe -i -H "X-Request-ID: demo-1" -H "x_demo_tag: literal" -b "theme=dark" "$exerciseBase/headers-cookies"
Invoke-RestMethod -Method Post -Uri "$exerciseBase/json" -ContentType "application/json" -Body '{"message":"hello"}'
Invoke-RestMethod -Method Post -Uri "$exerciseBase/form" -Body @{message="hello"}
curl.exe -i -F "label=demo" -F "file=@README.md;type=text/plain;filename=notes.txt" "$exerciseBase/upload"
curl.exe -i "$exerciseBase/errors/rate-limited"
~~~

The upload command sends the repository README bytes under the sample filename
notes.txt. To try your own file, change @README.md and the filename.

Linux/macOS (Bash/zsh):

~~~bash
exercise_base="http://127.0.0.1:8002"

curl -i -H 'X-Request-ID: demo-1' -H 'x_demo_tag: literal' -b 'theme=dark' "$exercise_base/headers-cookies"
curl -i -H 'Content-Type: application/json' -d '{"message":"hello"}' "$exercise_base/json"
curl -i --data-urlencode 'message=hello' "$exercise_base/form"
curl -i -F 'label=demo' -F 'file=@README.md;type=text/plain;filename=notes.txt' "$exercise_base/upload"
curl -i "$exercise_base/errors/rate-limited"
~~~

Expected statuses: 200 for the four input examples and 429 with Retry-After: 60
for the last example. Change filename=notes.txt to filename=notes.pdf to see
415; omit label to see 422. Use the
[T03 CRUD demonstration](T03_D3.md#7-run-and-demonstrate-the-main-api)
on the main API to inspect 201, 204, 404, and 409.
