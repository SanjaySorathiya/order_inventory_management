# T05 - Day 5: Pydantic v2 domain schemas

T05 adds distinct inventory create, full replacement, partial update, and read
contracts; order create/status-update/read contracts with nested order lines;
and login/public-user schemas. The contracts follow the baseline in
[T01_D1.md](T01_D1.md): money is integer INR minor units, quantities and IDs are
bounded integers, public user output omits credentials and internal flags, and
unknown fields are rejected at every JSON model boundary.

The login input models the password-form contract (`username`, `password`,
`grant_type=password`, and optional empty `scope`). `StaticCredentialVerifier`
checks the agreed local demo credentials `admin` / `password` behind a
`CredentialVerifier` protocol. T15 can replace the verifier with persisted-user
and password-hash checks without changing the login or public-user schemas.
The static verifier is a learning fixture, not a production credential store.

Integer IDs, quantities, stock, and monetary values are strict so booleans,
strings, and fractional numbers cannot be silently converted. Text fields use
Pydantic string validation and declared length/pattern constraints; inventory
SKU and login username are normalized by their annotated string constraints.
Read models use `from_attributes=True` in preparation for ORM-backed reads.

Order status transition permission, stock availability, duplicate line policy,
and transaction behavior remain service concerns for later tasks. Schemas only
constrain the request shape and lifecycle vocabulary.
